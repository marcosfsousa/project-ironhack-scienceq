# ── Imported by name, previously left to the resolver (#37) ──────────────────
# Every one of these is imported directly by api/ or agent/, so it is a direct
# dependency regardless of which parent package also happens to pull it in.
# Until now none was declared here, so their versions came from whatever the
# resolver picked at build time — two builds of the same commit could ship
# different versions of code the app imports, with no diff to review.
#
# Versions below are what a clean `--no-cache` build of Dockerfile — the image
# this file is the manifest for — resolved on 2026-07-28 (linux/amd64, py3.11,
# the Cloud Run runtime), read out with importlib.metadata. Re-derive against
# Dockerfile, not Dockerfile.pipeline: the pipeline image installs
# requirements-dev.txt, a superset whose extra pins tighten the solve. Both
# happen to agree on these four today, but they do not agree in general — the
# superset holds langchain-openai at 1.3.4 where this file alone floats it to
# 1.4.1. Never re-derive on a developer machine: environment markers differ by
# platform and a Windows resolve reports a different set.
#
# starlette is the reason this is not just tidiness. fastapi==0.140.10 declares
# `starlette>=0.46.0` with no upper bound, and the resolver has already walked
# that across a major version to 1.3.1. api/limiter.py and api/routes.py import
# starlette.requests.Request directly, so absent this pin the next major lands
# in the serving image on a rebuild with no manifest change.
#
# The trade this accepts: bumping fastapi now requires a deliberate matching
# starlette bump instead of letting it float. That is the point — do not remove
# this pin as redundant just because fastapi already depends on starlette.
# langchain-core carries the same trade in a tighter form: 1.5.1 sits exactly
# on the floor declared by langchain-openai 1.4.1 (`>=1.5.1`), and
# langchain-openai is itself transitive and unpinned, so one of its future
# releases can raise that floor and fail this build outright. That failure is
# loud and shows up in a diff, which is the trade working, not breaking.
#
# Scope, so the next reader is not misled: this pins what api/ and agent/
# import by name. The transitive tree still floats almost entirely (anyio,
# httpx, tenacity, numpy, ...) and there are no hashes, so builds are more
# reproducible than before, not reproducible. The one transitive held despite
# nothing importing it is limits, pinned at the bottom of this file under a
# two-clause criterion #41 settled; the block there states what makes it the
# exception and works through h11 under uvicorn, which meets the first clause
# and is still not pinned. Successor releases are watched
# now: .github/dependabot.yml (#40) opens a weekly PR when a newer release of
# a pin below exists, grouping fastapi+starlette and the langchain train so a
# coupled bump arrives as one reviewable diff. The floating transitive tree is
# covered from the other side: Dependabot alerts and security updates were
# enabled on the repo on 2026-07-28, and those read the full dependency graph
# rather than this file. That half is a repository setting, so no file here
# can guarantee it is still on. Bumps still merge by hand either way; the bot
# only surfaces them.

# ── Imported by shipped pipeline/ source, not by api/ or agent/ (#42) ────────
# Dockerfile COPYs pipeline/ wholesale into the serving image, so
# pipeline/sponsorblock.py:17 and pipeline/enrich_metadata.py:27 ship there and
# import requests by name — the same criterion the four above were pinned on.
# It was pinned only in requirements-dev.txt, which the API image never
# installs, so it floated here (2.34.2) while the pipeline image shipped
# 2.32.5: two production images, two versions of the same package.
#
# Nothing executed that import. live_ingest — the only pipeline module the API
# path reaches — imports cleaner, chunker and embedder, none of which touch
# requests; sponsorblock is imported lazily at chunker.py:180 inside the
# skip_sponsors branch of chunk_transcript, whose only caller is the batch
# entrypoint run(). The exposure was a future change to the ingest path
# reaching it and finding an undeclared version, not a live fault.
#
# Declared here rather than left in requirements-dev.txt because that file
# inherits this one via `-r`: the pipeline image resolves the same pin without
# restating it, so the two images converge on one version by construction.
#
# Converged up on 2.34.2 rather than down on the 2.32.5 requirements-dev.txt
# carried, because CVE-2026-25645 (GHSA-gc5v-m9x4-r6x2, medium, CVSS 4.4)
# affects < 2.33.0 — pinning down would have put the advisory in both
# production images instead of neither. It is not reachable from this codebase:
# the flaw is predictable temp-file naming in requests.utils.extract_zipped_paths(),
# which only direct callers hit, and both call sites here are a plain
# requests.get with params and a timeout (sponsorblock.py:36,
# enrich_metadata.py:73). Pinning to a flagged version anyway would buy nothing
# and cost every future image scan.
#
# The API image had already floated to 2.34.2, so this moves only the batch job,
# across 2.33.0 → 2.34.2. Runtime behaviour changed in that span only in greedy
# no_proxy matching and duplicate leading slashes in URI paths; neither touches
# a fixed-URL GET with no proxy set. The remainder is inline typing replacing
# typeshed, a PEP 517 build, and dropping Python 3.9 (both images are 3.11),
# plus two dependency floors 2.33.0 raised: urllib3 >=1.21.1 → >=1.26 and
# certifi >=2017.4.17 → >=2023.5.7. Both images resolve well clear of those
# (urllib3 2.7.0, certifi 2026.7.22), so they are recorded here, not a
# constraint to work around.

# ── Imported by nothing, and it is where rate limiting actually happens (#41) ─
# Nothing under api/, agent/ or pipeline/ imports limits, so the criterion the
# two blocks above rest on — a package shipped source imports by name is a
# direct dependency — does not reach it. It is pinned anyway, on a second and
# narrower criterion this block exists to state. The statement matters more
# than the pin: pinning packages nothing imports is what #29 had to undo when
# this file's dev counterpart carried streamlit's whole transitive tree, so an
# exception without a written boundary is just that mistake with better
# manners.
#
# The rule, in two clauses that have to be taken in order: pin an unimported
# transitive when (1) the pinned parent declares it with no upper bound, and
# (2) the parent is a thin wrapper over it — the child being where the
# behaviour lives. slowapi meets both. It declares `limits>=2.3` with no
# ceiling, and it supplies the decorator, the key function and the 429 handler
# (api/limiter.py, api/main.py:29-31) while limits supplies the window
# algorithm and the storage that every @limiter.limit(...) in
# api/routes.py:63,90,115 is evaluated by. Read out of the running image, the
# limiter behind those three decorators is limits' FixedWindowRateLimiter over
# limits' MemoryStorage — api/limiter.py passes neither, and slowapi resolves
# both out of limits by name: STRATEGIES["fixed-window"] and
# storage_from_string.
#
# Clause (1) is what most candidates fail, and failing it ends the question
# before judgment enters: starlette declares `anyio<5,>=3.6.2` and pydantic
# declares `pydantic-core==2.46.4`, so neither child can cross a major on a
# rebuild. A parent that later lifted its own cap would surface as a bump to
# that parent, in a diff. Only an unbounded declaration puts the child beyond
# review, which is the exposure this pin answers.
#
# Clause (2) is the judgment, and h11 under uvicorn is the case that shows
# where it stops. h11 clears clause (1) — `h11>=0.8`, no ceiling — is imported
# by nothing here, and is where HTTP/1.1 protocol behaviour actually lives, so
# it reaches the same question limits does. It is still not pinned, because
# uvicorn is not a thin wrapper over it: uvicorn is a server with config,
# lifespan, worker and signal handling, and h11 is one pluggable protocol
# implementation inside it. slowapi has no such surface of its own — strip
# limits out and nothing is left but the decorator. That is the line: is the
# parent's public behaviour the child's behaviour renamed, or does the parent
# merely run on the child. If it ever has to move, move it here in writing
# rather than package by package.
#
# The unbounded floor is not hypothetical: `limits>=2.3` has already been
# walked to 5.8.0, three majors, which is the starlette case above further down
# the same road. What those majors changed is the argument. 5.0.0 removed the
# fixed-window-elastic-expiry strategy outright, and slowapi selects a strategy
# by string key with `if strategy not in STRATEGIES: raise` — the set limits
# 5.8.0 offers is fixed-window, moving-window and sliding-window-counter, so a
# major that drops or renames the key this service defaults to takes rate
# limiting down at startup, from a rebuild with no manifest diff. 4.0.0 changed
# the reset value from get_window_stats from a truncated second to a float,
# which slowapi still annotates Tuple[int, int] and adds 1 to for its reset
# header; that one is inert here only because headers_enabled is False.
#
# Neither was noticed when it happened, because nothing here looks. No test
# under tests/ references the limiter, 429 or RateLimitExceeded, and CI builds
# no image (#39, #52), so this line is the whole of the defence. A check that
# the limiter still limits belongs with the image gate those two issues
# propose, not here — as written it would need a TestClient and so an httpx
# pin, which is a dependency decision of its own.
#
# Version derived from a --no-cache build of Dockerfile on 2026-07-28
# (linux/amd64, py3.11 — the Cloud Run runtime), read with importlib.metadata
# inside the image. Never re-derive on a developer machine. Dockerfile.pipeline
# resolves the same 5.8.0 through the `-r` inheritance, so this freezes a
# version both images already agree on rather than converging a split the way
# requests above did.
#
# The trade is starlette's in the same shape: a future slowapi that raises its
# limits floor past this pin fails the build instead of resolving quietly, and
# that failure lands in a diff. slowapi 0.1.10 — open as PR #55 in the
# fastapi-stack group — still declares `limits>=2.3`, so this pin survives that
# bump unchanged. limits is in that group too (.github/dependabot.yml), since a
# limits bump is not reviewable without the slowapi it runs under.
limits==5.8.0
